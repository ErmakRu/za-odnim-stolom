# Боты: запуск, behavior tree и bots.json

Рабочая ветка: `codex/urp-bots`, основа — `origin/urp` (`9f62b1c`). Боты работают в «Волшебниках» и «Полководцах», в локальном матче и под управлением Steam-хоста. Windows-билд 0.8.0 включает этих ботов и текущий стиль URP.

## Быстрый тест в Unity

1. Откройте `Assets/Scenes/MainMenu.unity` и нажмите Play.
2. Нажмите «За одним ПК», выберите 2–4 места.
3. Первое место — человек. По умолчанию остальные места — боты; кнопка под каждым портретом переключает «бот / игрок». Можно оставить нескольких людей за одним ПК.
4. Выберите колоды и режим. Нажмите «Начать матч».

При единственном человеке камера и интерфейс остаются на его месте, даже во время хода бота; чужая рука не раскрывается. При нескольких людях сохранена передача клавиатуры между людьми. Настройки/подтверждение выхода приостанавливают локальное время; Steam-матч продолжает идти.

В Steam лидер нажимает «Добавить бота» под свободным местом; под ботом доступно удаление. Хост может менять его колоду, персонажа и броню. Боты используют свободные места в пределах вместимости. Если до старта приходит человек, число отображаемых ботов уменьшается до свободной вместимости; человек не вытесняется. Боты не заменяют отключившихся участников уже начавшегося матча. Сетевой протокол — **10**, всем участникам нужна совместимая версия.

## Дерево по умолчанию

```text
root: selector
  finish: sequence → matchEnded → rematch
  round: sequence  → roundEnded → nextRound
  qte: sequence    → ownQte → qteKey
  reaction: sequence → reactionWindow → reactOrPass
  turn: sequence → myAction → selector
    playBest
    assignAttack
    endTurn
```

Дерево реактивное: перед каждым решением условия проверяются заново. Selector выбирает первую подходящую ветку; Sequence требует последовательного успеха условий. Действие, сформировавшее команду, возвращает Running и останавливает обход на этом тике. За тик каждый бот отправляет не больше одной команды. Дальнейшее решение ждёт настроенную задержку.

Бот видит только собственную руку, публичные счётчики чужих рук, стол и открытый розыгрыш. Он получает `GameEngine.View(своё место)`; последовательность QTE другого игрока ему недоступна. Его команды проходят обычный `GameEngine.Submit`: стоимость QTE, лимиты заклинаний/существ, места на столе и окна реакций проверяются тем же движком, что для человека.

В свой ход бот оценивает законные карты и один следующий розыгрыш. В «Волшебниках» немного выше вес заклинаний; в «Полководцах» дополнительно учитывается полезность относительно стоимости QTE. Полководец может вызывать несколько существ, пока хватает общего бюджета. После розыгрышей бот назначает цели своим существам, заново оценивая их каждый ход, и завершает ход. Предпочитает добивание героя, полезное устранение существа и лечение себя. Реакции выбирает при показе/QTE; во время атаки уже стоящих существ реакций нет.

## Верхний уровень JSON

| Поле | Значение / смысл |
| --- | --- |
| `schemaVersion` | Версия схемы; сейчас 1 |
| `defaultLocalBotSeats` | Места, которые при первом входе в локальное лобби будут ботами. Нумерация с 0, разрешены уникальные 1–3. Место 0 остаётся человеком |
| `autoRematch` | Автоматический голос ботов «сыграть ещё раз». По умолчанию true. При false боты не голосуют; для продолжения нужен новый матч/пересборка состава лобби |
| `profiles` | Ровно два профиля: `wizards` и `commanders` |
| `profiles[].mode` | Режим, которому принадлежит профиль |
| `profiles[].root` | ID корневого узла |
| `profiles[].timing` | Задержки и вероятность правильного символа |
| `profiles[].weights` | Оценки решений и приоритеты |
| `profiles[].effects` | Дополнительные оценки постоянных эффектов существ |
| `profiles[].nodes` | Узлы дерева с ID и ссылками на дочерние узлы |

## Задержки и QTE

Время задаётся в секундах игрового времени. Диапазоны включают min/max; нижняя граница должна быть больше нуля, верхняя не меньше нижней. Ошибки QTE подчиняются обычным штрафам, срыву и передаче карты.

| Поле timing | По умолчанию | Назначение |
| --- | --- | --- |
| `thinkMin` | 0.45 | Минимальная пауза перед обычным решением |
| `thinkMax` | 0.9 | Максимальная пауза перед обычным решением |
| `reactionMin` | 0.55 | Минимальное время ответа на новый розыгрыш |
| `reactionMax` | 1.1 | Максимальное время ответа на новый розыгрыш |
| `qteMin` | 0.24 | Минимальная пауза между символами собственного QTE |
| `qteMax` | 0.48 | Максимальная пауза между символами собственного QTE |
| `qteCorrectChance` | 0.97 | Вероятность верного символа, 0–1; это НЕ вероятность успеха всего QTE |
| `retrySeconds` | 1 | Задержка после команды, отвергнутой движком |

## Узлы и быстрое изменение поведения

Каждый узел имеет `id`, `type`, `operation`, `children`. У selector/sequence список children содержит ID узлов в порядке обхода, operation пуст. У condition/action список children пуст, operation задаёт одну из поддерживаемых операций. Идентификаторы уникальны. Все узлы должны быть достижимы от root; циклы, неизвестные операции и ссылки не сохраняются. Максимум 128 узлов на профиль; ветка endTurn должна присутствовать.

| Тип | Операции |
| --- | --- |
| condition | `ownQte`, `reactionWindow`, `myAction`, `roundEnded`, `matchEnded` |
| action | `qteKey`, `reactOrPass`, `playBest`, `assignAttack`, `endTurn`, `nextRound`, `rematch` |

Например, чтобы сначала назначать атаки, а потом разыгрывать карты, замените у узла `turn.options`:

```json
"children": ["aim", "play", "end"]
```

Порядок остальных узлов сохраняется. Чтобы бот всегда выбирал конкретную цель, установите `randomTargetChance: 0`. Чтобы убрать ошибки QTE, задайте `qteCorrectChance: 1`. Для более быстрой игры уменьшите положительные диапазоны timing. После сохранения перезагрузите Config и запустите новый матч.

Новая принципиальная операция дерева реализуется в `BotBrain.Act`/`Condition` и добавляется в список поддерживаемых операций. Перестановка существующих узлов, изменение приоритетов и сложности выполняются через JSON без изменения кода.

## Ограничения и проверки

Это простой эвристический бот с оценкой одного следующего розыгрыша. Он не прогнозирует всю партию, неизвестную руку соперника или случайный порядок колоды. Оценка эффектов приближённая; итоговое действие всегда перепроверяет движок.

Отчёты: [проверки правил и симуляций](../output/tests/bots-tests.txt), [тест в Play Mode](../output/tests/bots-editor-play.txt), [сохранение/откат Manager](../output/tests/bots-config.txt). Они проверяют два режима, 2–4 места, стоимость действий, приватность, реакции, слоты, изменение JSON-дерева и повторный матч. Steam-метаданные и разделение человеческих/бот-команд проверены программно; совместный Steam-матч на нескольких ПК требует отдельного прогона.
