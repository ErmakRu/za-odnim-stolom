# Комиксы кампании «Пир Хохота»

Рабочая ветка: **script&chars**. Исходники — `story_script.md` и `Assets/StreamingAssets/Config/story.json` из этой же ветки. Новый модуль находится целиком в `Assets/Campaign`, кроме трёх точек подключения к `GameApp`, кнопки основного меню и общего Inspector JSON.

## Запуск и управление

1. В Unity: **Summoners Table → Campaign → Open campaign**, затем **Play**. То же самое: открыть `Assets/Campaign/Scenes/Campaign.unity`.
2. Или открыть обычную сцену `MainMenu` и нажать **Кампания · Пир Хохота**.
3. Выбрать одну из трёх готовых колод, продолжить сохранённый путь или начать заново.
4. **Дальше / Пробел / Enter** сначала допечатывает текст, затем переключает реплику. **Назад / ←** возвращает предыдущую реплику внутри текущей части. **Пропустить пролог / К поединку** завершает текущую часть.
5. После последней реплики перед поединком кнопка запускает настоящий матч 1 на 1 против бота. Действуют обычные правила выбранного в главе режима, QTE, реакции и атаки в конце хода. Чужая рука и чужой QTE скрыты.
6. Победа открывает продолжение сюжета, поражение или ничья — повтор поединка. Через результаты можно сменить колоду или выйти. После 17 побед воспроизводится эпилог.

Прогресс автоматически сохраняется в `Application.persistentDataPath/campaign-progress.json`: глава, часть, кадр, реплика, выбранная колода. Незавершённый бой при продолжении начинается заново с комикса перед ним. Победа сохраняется до нажатия «Продолжить историю». Локальные/Steam-матчи этот файл не меняют.

## Что редактировать

| Файл / объект | Назначение |
| --- | --- |
| `Resources/Campaign/CampaignComic.prefab` | Общий префаб: фон, герой слева, персонаж справа, имена, окно диалога, кнопки, выбор колоды, звук. Изменение его разметки меняет все комиксы |
| `Resources/Campaign/campaign.json` | **Единый редактируемый сценарий** всех 17 поединков, пролога и эпилога |
| `Resources/Campaign/Media.asset` | Прямые ссылки на существующие в проекте звуки; ключ — имя WAV с расширением |
| `Scenes/Campaign.unity` | Точка входа в режим для Play из редактора |
| `coverage.json` | Проверка переноса, список временных портретов и отсутствующих аудиофайлов |
| `Tools/build_campaign.py` | Одноразовый конвертер старого `story.json`. **Не запускается автоматически**. Повторный ручной запуск перезапишет новое оформление/правки JSON |
| `Runtime/GameCampaign.cs` | Переходы между сюжетом, матчем и результатами; сохранение прогресса |
| `Runtime/CampaignComicView.cs` | Заполнение префаба, печать текста, клики и звук |

PNG персонажей по-прежнему лежат в `Assets/Resources/Art/Jester` и `Others`. Исходные сценарии и старый `StoryNovelManager` сохранены, но новый режим их в рантайме не запускает: он читает только `campaign.json`.

В будущем готовом билде можно положить `campaign.json` в папку `Config` рядом с EXE: внешний файл имеет приоритет перед встроенным `Resources/Campaign/campaign.json`. Новые PNG и WAV сначала нужно добавить в Unity-проект и включить в следующую сборку. В этой итерации Windows-билд не создавался.

## Редактирование через Inspector

Выберите JSON в Project либо **Summoners Table → Campaign → Edit comic JSON**. Он открывается в **Inspector**, а не во внешней программе.

Выберите часть, для поединка — «До боя» или флажок «После победы», затем кадр и реплику. Меняйте текст, говорящего, картинки, эмоцию Шута, масштаб и смещение персонажей. Кнопки **Добавить кадр** и **Добавить реплику** создают новые элементы. Нажмите **Сохранить**. При ошибке в данных файл не перезаписывается; **Перечитать / отменить** возвращает сохранённый вариант. Если файл параллельно изменился на диске, Inspector требует перечитать его.

Для добавления ещё одной главы или настройки редких параметров раскройте **Исходный JSON (все параметры)**, измените текст, нажмите **Применить JSON к полям**, затем **Сохранить**. Данные перечитываются при открытии кампании. Уже начатый матч продолжает использовать свои правила.

## Структура JSON

```json
{
  "schemaVersion": 1,
  "title": "Пир Хохота",
  "defaultDeck": "noise",
  "charactersPerSecond": 65,
  "ambienceVolume": 0.22,
  "sfxVolume": 0.6,
  "introduction": [],
  "chapters": [
    {
      "id": "b01_zhabadushess",
      "title": "ЖабаДушэс",
      "opponentName": "ЖабаДушэс",
      "opponentDeck": "tricks",
      "opponentHero": "badger",
      "mode": "wizards",
      "seed": 1701,
      "before": [],
      "after": []
    }
  ],
  "ending": []
}
```

Этот фрагмент иллюстрирует структуру: перед запуском `before` нужно заполнить хотя бы одним кадром с репликой.

| Параметр | Значение / смысл |
| --- | --- |
| `schemaVersion` | Версия схемы, сейчас `1` |
| `title` | Название на экране кампании |
| `defaultDeck` | ID стартовой колоды из `Config/decks.json`: `noise`, `cozy`, `tricks` |
| `charactersPerSecond` | Скорость появления букв, 0–500; `0` сразу показывает всю реплику |
| `ambienceVolume`, `sfxVolume` | Громкость 0–1; дополнительно применяются общая громкость и соответствующий звуковой канал настроек игры |
| `introduction` | Кадры пролога, детства и знакомства с таверной |
| `chapters` | Упорядоченные главы: одна запись — один бой. Между ними нельзя случайно пропустить бой кнопкой перехода диалога |
| `ending` | Кадры эпилога, только после последней победы |
| `chapter.id` | Уникальный постоянный ID поединка |
| `title` / `opponentName` в главе | Название главы / имя соперника в матче |
| `opponentDeck` | ID одной из существующих колод; собственная колода босса в исходнике пока сопоставлена `tricks` |
| `opponentHero` | Аватар за 3D-столом: `badger`, `deer`, `dog`, `lion`, `lizard`, `owl`, `rabbit`, `rat` |
| `mode` | `wizards` — Волшебники; `commanders` — Полководцы. В текущем наборе Полководцы в боях 4, 8, 12 и 16 |
| `seed` | Зерно раздачи и случайностей поединка; при повторе начальная раздача воспроизводима |
| `before` | Кадры до боя; последняя реплика даёт кнопку «Начать поединок» |
| `after` | Кадры после победы; затем начинается следующая глава или эпилог |

## Кадр, персонажи и реплики

```json
{
  "id": "b01-before-f01",
  "title": "Первая дуэль",
  "background": "LayeredCards/Layers/S01/background",
  "left": {
    "art": "Art/Jester/jester_basic",
    "label": "Йорик", "portrait": false,
    "scale": 1, "offsetX": 0, "offsetY": 0
  },
  "right": {
    "art": "Art/Others/mainKing",
    "label": "Малхорат", "portrait": false,
    "scale": 1, "offsetX": 0, "offsetY": 0
  },
  "lines": [
    {
      "sourceId": "custom.1",
      "speaker": "ШУТ",
      "text": "Сдавайте карты!",
      "leftArt": "Art/Jester/jester_happy",
      "sfx": "Card_Game_Movement_Shuffle_01.wav",
      "ambience": "Card_Game_Ambience_Pasture.wav"
    }
  ]
}
```

| Параметр | Назначение |
| --- | --- |
| `frame.id` | Уникальное имя кадра внутри части; не путать с ID боя |
| `frame.title` | Описание кадра для редактора; используется в заголовке пролога |
| `background` | Путь к Texture2D относительно **Resources**, без расширения и без префикса `Assets` |
| `left`, `right` | Слоты персонажей: герой слева, собеседник/противник справа |
| `actor.art` | Путь к PNG в Resources. Пустая строка скрывает персонажа |
| `label` | Подпись под персонажем |
| `portrait` | `true` — компактный портрет в рамке, `false` — силуэт с прозрачностью. Заменяя временную иллюстрацию полноценным PNG персонажа, выключите этот флажок |
| `scale` | Дополнительный равномерный масштаб 0.2–3. Пропорции PNG сохраняются |
| `offsetX`, `offsetY` | Смещения от своего места в единицах холста 1600×1000; вправо/вверх — положительные значения |
| `lines` | Реплики этого кадра; фон и персонажи сохраняются между ними |
| `sourceId` | Необязательная метка для поиска строки в исходном сценарии; при переносе сохранены исходные номера |
| `speaker` | Имя говорящего над текстом |
| `text` | Реплика. Отображается как обычный текст, без исполнения команд из неё |
| `leftArt` | Смена эмоции Шута для этой реплики. Пустая строка использует `left.art` кадра |
| `sfx` | Имя WAV из `Media.asset` или `action:qte.correct` / другое событие `audio.json`; пустая строка — без нового звука |
| `ambience` | Имя WAV в цикле; пустая строка продолжает предыдущий фон, `Mute` останавливает его |

Шут имеет два исходных рисунка (`jester_basic`, `jester_happy`). У остальных эмоции можно менять отдельными кадрами с другим `right.art`. Чтобы добавить звук, сначала импортируйте WAV в проект, затем добавьте запись в `Media.asset`. Имя должно точно совпадать с ключом в JSON. Автоматическое обновление реестра имеющихся звуков — `CampaignAuthoring.Create` (используется при разработке; существующий префаб не пересоздаёт).

## Материалы и адаптация сценария

Перенесены **все 111 исходных реплик**, без потерь и дубликатов: 17 боёв, пролог, обучение, таверна, победные сцены, эпилог. Реплики обучения `1.4`, `1.9`, `1.10` адаптированы: добор в начале хода, ручные цели существ, атаки в конце хода, реакции только на розыгрыш. Исходные файлы не изменены.

В `Others` сейчас имеется только Малхорат. Для других собеседников используются **временные портреты из существующих карточных артов**; это не новые полноценные рисунки персонажей сценария. Список сопоставлений — `coverage.json`. Фоны пока переиспользуют имеющиеся чистые иллюстрации таверны; отдельные дворец, цирк и остальные сюжетные локации не рисовались. Заменить их можно независимо у каждого кадра.

`boss_golden` в исходнике пока не является отдельной игровой колодой: финальный соперник использует готовую колоду `tricks`. Режимы противников перечислены в JSON; специальные правила боссов поверх базовой игры не добавлялись. Логика ботов общая, настраивается в `Config/bots.json`.

Два указанных сценарием звука не найдены: `Action_Wind_Blast_01.wav`, `Card_Game_Action_Tear_Fire_01.wav`; их места оставлены без звука. Все остальные указанные дорожки разрешаются через реальные ассеты.

## Проверки и запись

- `CampaignTests.Run`: 17 полных автоматических боёв, команды ботов без ошибок, все картинки и колоды, 111 исходных реплик, отсутствие переполнения текстового поля, первый/второй клик, сохранение/загрузка прогресса и отклонение неизвестной колоды.
- `CampaignRecording.Run`: запускает настоящий Editor Play, кликает элементы того же префаба, пропускает пролог штатной кнопкой, показывает комикс первого боя, затем выполняет допустимые игровые команды. Тестовые сохранения пишутся отдельно в `tmp/campaign-record`.
- `CampaignRecording.RunFlow`: проверяет в Play повтор после поражения, переход после победы, смену колоды, эпилог и выход. Итоги боёв здесь подставляются для проверки обеих веток интерфейса; сами бои отдельно проверяет `CampaignTests.Run`.
- `output/campaign/campaign-opening.mp4` в корне репозитория — запись начала: 1600×1000, 12 кадров/с, без аудиодорожки. Видео демонстрирует начало боя, а не полное прохождение всех 17 глав.
- `output/campaign/prologue.png`, `before-battle.png`, `battle-qte.png`, `battle-table.png` — реальные кадры Unity.
- Отчёты: `output/tests/campaign.txt`, `campaign-play.txt` и `campaign-flow.txt`.

Для записи используется [Unity PlayModeWindow.SetCustomRenderingResolution](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/PlayModeWindow.SetCustomRenderingResolution.html). Рендер комикса и игры выполняется Unity URP; видео не сгенерировано нейросетью. Кодирование: `python Assets/Campaign/Tools/encode_campaign.py` из папки проекта Unity либо полный путь к скрипту из корня репозитория.
